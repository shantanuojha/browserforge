# Reroute — URL rewrite rules

Store slot 2. Free core + $9 one-time Pro.

## Why it exists

Redirector (100K users) died with MV2 and its creator's passing; its two Featured successors (20K
and 10K) each miss transforms, SPA/history-state redirects or faithful import. ClearURLs' 100K Chrome
users lost their tracking-parameter stripper and its maintainer formally gave up on Chrome. Both jobs
are "rewrite this URL by rule", which keeps Reroute single-purpose.

## Scope (Phase 4)

Free:

- Rule model: `{ id, name, enabled, matchType: "wildcard" | "regex", include, exclude[], redirectTo,
resourceTypes[], transforms: ("decodeURIComponent" | "encodeURIComponent" | "atob" | "btoa" |
"lower" | "upper")[], applyTo: "navigation" | "all" }` with `$1..$9` capture groups.
- Engine in `src/lib/engine/`:
  - `compileToDNR(rules)` → `chrome.declarativeNetRequest` dynamic rules using `regexFilter` +
    `regexSubstitution` (RE2-safe subset check) for rules with no transforms; validate with
    `declarativeNetRequest.isRegexSupported`.
  - `jsFallback` in the background: `webNavigation.onBeforeNavigate` and `onHistoryStateUpdated`
    (SPA, e.g. YouTube Shorts → watch) → compute target with full JS regex + transforms →
    `tabs.update`. Loop protection (same URL, N hops).
  - Deterministic rule ordering; a `test(url)` function used by the rule tester UI.
- Tracking-parameter cleaner: `scripts/build-tracking-rules.ts` converts the ClearURLs catalog
  (`https://rules2.clearurls.xyz/data.minify.json`, LGPL-3 — keep attribution in
  `public/rules/ATTRIBUTION.md`) into static DNR `redirect.transform.queryTransform.removeParams`
  rules written to `public/rules/tracking-params.json` at build time (checked in, regenerated by a
  script, never fetched at runtime). Per-site allowlist toggles via `updateEnabledRulesets` +
  dynamic allow rules. Context-menu "Copy clean link".
- Importers: Redirector JSON (fields `includePattern`, `excludePattern`, `redirectUrl`,
  `patternType` wildcard|regex, `processMatches` noProcessing|urlDecode|urlEncode|base64decode,
  `appliesTo`), ClearURLs allowlist. Exporter to our JSON.
- Options page: rule list with enable toggles, editor with live tester, import/export, per-site
  allowlist, "what fired recently" log via `declarativeNetRequestFeedback` (`onRuleMatchedDebug`
  only in unpacked builds) plus our own JS-fallback log.
- Popup: on/off for this site, count of rules active, quick "clean this link".

Pro (feature ids: `sync`, `rule-packs`, `share`):

- `storage.sync` mirroring of rules (chunked, compressed), curated rule packs, shareable rule-set
  export links (encoded in URL, no server).

## Tests

Port fixture cases from Redirector's README/examples and from the ClearURLs test corpus. Cover:
wildcard→regex conversion, capture groups, each transform, exclude patterns, RE2 compatibility
detection, DNR rule generation shape, importer round-trips, loop protection.

## Constraints

- No remote code or runtime rule fetching; the catalog is compiled at build time.
- `<all_urls>` host permission is needed for `modifyHeaders`-free redirects on any site; document the
  justification for the store listing.
